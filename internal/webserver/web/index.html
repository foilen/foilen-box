Discovery

Server mode also stores and serves DHT records for other peers on the public network, which helps overall network health at the cost of some extra bandwidth and storage. Client mode only looks up records for yourself.

Known peers not seen (and currently disconnected) for this many days are automatically removed. 0 uses the default (14 days); -1 disables this and keeps peers forever.

NAT traversal

UPnP/NAT-PMP port mapping and NAT hole punching are always on, so peers behind a NAT can usually still connect directly.

Lets other group members reserve a relay slot on this peer and be reached through it when they're otherwise unreachable. Only useful if this peer is itself publicly reachable (e.g. a VPS); costs it some bandwidth on their behalf.

Web listener

Adds a websocket listener alongside the normal ports, so this peer stays dialable through firewalls/proxies that only allow common web ports out. Only useful for a peer with a stable public hostname/IP (e.g. a VPS); binding a port below 1024 needs OS permission the app may not have. Changing these settings restarts Realm's networking.

With "wss", the certificate is self-signed and not meant to be trusted on its own: peers accept it because the real authentication happens afterwards, via Realm's own peer-identity handshake. Use "ws" only when a reverse proxy in front of this peer already terminates TLS.

The announce hostname/port/protocol is what other peers are told to dial; it's required since this address can't be auto-discovered. Set announce port/protocol when a reverse proxy exposes a different public port (typically 443/wss) than the port this process actually binds locally.
